Revisa solo después de contestar todo
Dile a Claude qué números fallaste al empezar la siguiente sesión: entran al banco de repaso.
  1. State, nodes y edges. El state es la "memoria compartida" del grafo (un TypedDict). Los nodes son funciones que reciben el state y devuelven un update. Los edges dicen qué node sigue, ya sea fijo o condicional.
  2. foo = 2. Sin reducer, el update sobrescribe la key. El node no modifica el state directamente: devuelve un update y LangGraph lo aplica.
  3. Para que los mensajes se acumulen. Con una lista normal, cada node borraría el historial. add_messages agrega los mensajes nuevos al final y, si llega uno con un id que ya existe, lo reemplaza.
  4. Si el último mensaje (un AIMessage) trae tool_calls. Si los trae, va a tools; si no, va a END. El edge no ejecuta nada: solo lee el mensaje y elige la ruta.
  5. {"graph_state": "Hola soy triste"}. "Hola soy" tiene 8 caracteres, y 8 > 8 es falso, así que va a node_3.
  6. {"graph_state": "Hola! soy feliz"}. "Hola! soy" tiene 9 caracteres, y 9 > 8 es verdadero, así que va a node_2. La decisión se toma con el state después de node_1.
  7. [Human(id="1", "hola"), AI(id="2", "buenas")]. Siguen siendo dos mensajes, no tres: el id "2" ya existía, así que lo reemplaza. Con un id nuevo, se habría agregado al final.
  8. START → assistant. Desde assistant sale un edge condicional (tools_condition) que va a tools o a END. Desde tools se regresa a assistant. Ese regreso es el "loop" de ReAct.
  9. START → node_1 → (decide) → node_3 → END. node_2 existe en el grafo pero no se visita con "Hola".
